# dsh-cursor-context

Бандл DSH: записывает реальный объём контекста для моделей Cursor, которые его не публикуют.

Адаптер `cursor-to-dsh` вычисляет `context.contextWindow` из каталога Cursor: берёт параметр `context` модели и предпочитаемый уровень (`256k`, `500k`, `1m`). У модели без такого параметра опубликованного объёма нет вообще, и адаптер подставляет плоское значение `200000`. Для `deepseek-v41-flash-1017` это ошибка на порядок: маршрут реально принимает около одного мебибайта, но DSH записывает 200 000, а порог сжатия, выведенный из этого числа, начинает конденсировать историю слишком рано и показывает в интерфейсе бессмысленный процент заполнения.

Плагин исправляет записанный объём, не меняя пакет адаптера.

## Как это работает

1. Плагин находит на `llm.adapters` уже зарегистрированный адаптер настроенного провайдера.
2. Ставит на этот экземпляр собственное свойство `resolveModel` — обёртку над исходным методом.
3. Обёртка сначала вызывает исходный метод, поэтому имя, модальности, усилия рассуждения и режим системного промпта остаются точно такими, какими их вернул адаптер.
4. Затем она спрашивает таблицу ёмкости, какое значение записать вместо полученного, и возвращает новый объект модели с заменённым `context.contextWindow`.
5. `LlmAdapter.prepareCall` читает `this.resolveModel`, поэтому через обёртку проходят подготовка каждого запроса, `resolveModelInfo` и разбор каталога.

Ничего не регистрируется заново: `DUPLICATE_ADAPTER` невозможен, и объект адаптера сохраняет тождественность, поэтому `replayState` на исторических сообщениях ассистента остаётся привязанным.

## Таблица ёмкости

Два уровня, в порядке приоритета:

| Уровень | Когда применяется |
| --- | --- |
| `contextWindows[<id>]` | Всегда, когда модель указана явно. Побеждает и модель, публикующую свои уровни. |
| `defaultContextWindow` | Только к моделям, у которых в каталоге Cursor нет параметра `context`. |

Широкое значение по умолчанию намеренно не трогает самодостаточные модели: `grok-4.7`, например, публикует `256k` и `500k`. Записать поверх них один общий объём значило бы завысить ёмкость и отложить сжатие за настоящий предел — тогда запрос падает, вместо того чтобы конденсировать историю.

## Конфигурация

| Ключ | По умолчанию | Смысл |
| --- | --- | --- |
| `enabled` | `true` | Выключает плагин целиком: маршрут остаётся с тем объёмом, который вернул адаптер. |
| `provider` | `cursor` | Маршрут, чей адаптер оборачивается. |
| `defaultContextWindow` | `1048576` | Объём для моделей без опубликованного уровня. `null`, `false` или `0` отключают значение по умолчанию, оставляя карту явных записей. |
| `contextWindows` | `{}` | Точные объёмы по идентификатору модели. |

Пример строки в пользовательском слое профиля:

```yaml
- id: cursor-context
  name: dsh-cursor-context
  config:
    enabled: true
    provider: cursor
    defaultContextWindow: 1048576
    contextWindows:
      deepseek-v41-flash-1017: 1048576
```

Некорректное значение не ломает активацию: оно отбрасывается, а при активации печатается одна строка `[REJECT]` с объяснением. Принимаются только положительные целые числа (числом или строкой из цифр).

## Установка

```
plugin_manager install_bundle {"target": "/Users/alex_quidditch/projects/dsh-plugins/dsh-cursor-context"}
```

Новый бандл активируется по HMR; замену уже установленного пакета нужно подтвердить перезапуском. Проверять активацию следует по полям `application` и `warnings` в результате установки, а не по логам.

После активации новая сессия должна записывать в `request/context` и в проекции `contextPressure` значение `1048576` для `cursor/deepseek-v41-flash-1017`.

## Ограничения

* Плагин меняет только записанный объём, а не реальный предел провайдера. Если Cursor отклонит запрос из-за объёма, завышенное значение не поможет, а помешает: сжатие начнётся позже настоящего предела.
* Обёртка живёт на экземпляре адаптера и учитывает число активных копий плагина: при горячей перезагрузке новая копия успевает активироваться раньше, чем старая освободится, поэтому снос устаревшей копии лишь уменьшает счётчик. Если другой плагин заменит `resolveModel` после активации, при выключении восстанавливать будет нечего: плагин видит чужой владелец и оставляет метод ему.
* Каталог Cursor читается через `adapter.models()`, а он кэширован адаптером на десять минут. Свежесть каталога плагин не ускоряет.
