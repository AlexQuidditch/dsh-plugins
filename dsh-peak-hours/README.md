# dsh-peak-hours

Одна поверхность для пиковых часов DeepSeek: **индикатор в шапке сессии** с переключателем
«Разрешить работу в peak hours» и **хост-гейт**, который эту политику применяет.

Пакет заменяет два прежних (`dsh-peak-indicator` + `dsh-vv-peak-hours`): раньше индикатор
и гейт жили порознь и расходились — индикатор считал окна только по будням и держал их
в клиенте, а гейт брал окна из конфига без недельного фильтра. Теперь расписание одно:
его рендерит пилюля и по нему же решает `llm/stream`.

## Что делает

- **Индикатор** (`conversation.session.header.utilities`): точка + текст
  («пик через 12 мин» / «конец пика через 1 ч 20 мин» / «пик · разрешён»). Красная пульсация
  в пик, янтарная — когда работу в пик разрешили вручную.
- **Поповер по клику**: текущее состояние, время до переключения, режим гейта, окна в твоём
  часовом поясе и чекбокс **«Разрешить работу в peak hours»**.
- **Гейт** (`llm/stream`, prepend+global): `soft` пишет предупреждение в лог хоста,
  `hard` отклоняет вызов ошибкой `PEAK_HOURS_BLOCK` до всякой работы адаптера.

## Переключатель важнее режима

`soft` пишет только в лог хоста — то есть в stdout процесса `dsh web`, где никто не смотрит.
Поэтому переключатель — настоящий выключатель гейта: при включённом override вызовы проходят
и в `hard`, и в `soft`. Выбор **сохраняется** в `$DSH_HOME/peak-hours.json`, чтобы перезапуск
не возвращал блокировку, которую пользователь только что снял.

## Матчинг провайдеров

Ключ расписания — **семейство**, а не id рантайма. Правило (`resolveSchedule`):

1. точный ключ выигрывает всегда (`deepseek-vision` может нести свои окна и свой `mode`);
2. иначе — самый длинный ключ, являющийся префиксом id по разделителю `-`
   (`deepseek` → `deepseek-official`, `deepseek-vision`), но `deep` ≠ `deepseek`;
3. иначе гейт открыт, как для неизвестного провайдера.

Именно на этом гейт молчал: конфиг писал `deepseek`, а `options.provider` приходит как
`deepseek-official`.

## Конфиг (`cordis.patch.yml` бандла)

```yaml
config:
  enabled: true
  mode: soft                     # hard — блокировать вместо предупреждения
  schedules:
    deepseek:                    # семейство: deepseek / deepseek-official / deepseek-vision
      windows:
        - { start: "01:00", end: "04:00", tz: "UTC", days: [1, 2, 3, 4, 5] }
        - { start: "06:00", end: "10:00", tz: "UTC", days: [1, 2, 3, 4, 5] }
    zai:                         # семейство: провайдер zai (glm-5.3, glm-5.3-flash, zai-*)
      windows:
        - { start: "14:00", end: "18:00", tz: "Asia/Shanghai", days: [1, 2, 3, 4, 5] }
```

`days` — 0=вс..6=сб; уберите ключ, чтобы окно действовало каждый день. Окна могут пересекать
полночь. Битое окно и неизвестный провайдер — fail-open (warn, никогда не блок).

## Откуда взяты окна

**DeepSeek** — страница цен: 01:00–04:00 и 06:00–10:00 UTC, пн–пт.

**GLM Coding Plan** (Z.ai / 智谱) — [docs.bigmodel.cn/cn/coding-plan/overview](https://docs.bigmodel.cn/cn/coding-plan/overview),
раздел «积分抵扣计算方式»:

> 非高峰时段内，模型调用按基础积分消耗的 50% 抵扣。
> 高峰时段：每周一至周五的 14:00～18:00（UTC+8）。

То есть в не高峰 (вне окна) вызовы списывают 50% базовых кредитов, а高峰 — это
**пн–пт 14:00–18:00 по Пекину** (= 06:00–10:00 UTC). Окно объявлено в
`Asia/Shanghai`, поэтому день недели движок считает по Пекину, а не по UTC;
выходные в план целиком идут по не高峰 и в расписании их нет.

Провайдер в этом харнессе называется `zai` (регистрируется `llm-pi-ai` с
`baseURL: https://api.z.ai/api/coding/paas/v4`), поэтому ключ семейства — `zai`.
Если появится ещё один GLM-маршрут под другим id, добавьте ему ключ: матчинг идёт
по id провайдера, а не по имени модели.

> **Кампания 庆双节 (2026-09-25 … 2026-10-07)** в плане списывает *любой* час по
> правилам не高峰, так что до её конца запись `zai` не сработает ни разу — это
> кампания, а не сломанное расписание. Отдельно идёт «夜间畅用» (2026-09-03 …
> 2026-10-07, 23:00–09:00 по Пекину): он даёт ×2 кредитов на GLM-5.3-Flash и не
> влияет на高峰-окно.

## Установка

```bash
dsh plugin --profile web add ~/projects/dsh-plugins/dsh-peak-hours
# затем перезапуск dsh web: хост-половина (гейт + канал) грузится на старте процесса
```

Клиентская половина обновляется обычной перезагрузкой страницы, хост-половина — только
перезапуском: перемонтирование строки не переимпортирует изменённый модуль.

## Тест

```bash
node activation.test.mjs   # движок, гейт, канал и регистрация индикатора
```

`$DSH_HOME` подменяется временным каталогом, живой DSH не трогается.
