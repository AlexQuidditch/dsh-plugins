# vv-handoff

Порт vv-handoff из vv-opencode: заметка передачи контекста между сессиями. Пишется ТОЛЬКО из уже видимого контекста — никаких новых расследований.

## Процедура

1. Определи slug сессии (короткий, по теме работы; например `cache-refactor`).
2. Создай `.vvoc/handoff/YYYY-MM-DD-<session-slug>/handoff.xml` (дата — сегодня).

## Формат

```xml
<handoff session="<session-slug>" created_at="YYYY-MM-DD">
  <goal>Чего сессия должна была добиться.</goal>
  <status>Честная оценка: done / in-progress / blocked.</status>
  <progress>
    <done>Сделанное, с путями к артефактам (включая .vvoc/specs/*).</done>
  </progress>
  <decisions>
    <decision>Решение и почему. Ссылка на файл/строку, где оно зафиксировано.</decision>
  </decisions>
  <blockers>
    <blocker>Что мешает дальше и что уже пробовали.</blocker>
  </blockers>
  <next_steps>
    <next_step>Первый конкретный шаг следующей сессии.</next_step>
  </next_steps>
  <open_questions>
    <open_question>Вопрос, ждущий пользователя.</open_question>
  </open_questions>
</handoff>
```

## Правила

- **Только видимый контекст**: этот чат, прочитанные файлы, результаты инструментов. Не запускай новые проверки ради заметки.
- **Редакция секретов обязательна**: токены, ключи, пароли, приватные email не попадают в файл — вместо них пометки `<redacted/>` или тип значения.
- Файл пишется так, чтобы следующая сессия могла продолжить БЕЗ этой: пути к артефактам, команды, причины решений.
- Если уже есть handoff за сегодня по той же теме — обнови его, не плоди.
- Кратко: заметка — мост, а не лог. Не дублируй чат.

## Выход

Сообщи путь к заметке и одну строку резюме. Не начинай новую работу.
