# dsh-plugin-workspace-policy

Хост-плагин DSH (DeepSeek Harness): **per-workspace политика маршрута LLM**.
Файл `.dsh/workspace.yaml` в корне воркспейса задаёт, на какой модели стартуют
мастер-сессии этого воркспейса, на какой — все дочерние агенты, и куда
деградировать при терминальном отказе основного маршрута. Плагин применяет
политику на шве `agent/request` — единственной точке, через которую проходит
**каждый** разговорный запрос **каждого** агента процесса, — и не трогает
глобальный `agent-default-model` в `settings.yaml`.

## Мотивация

Сегодня единственный механизм «с какой модели стартует сессия» —
`agent-default-model` в `~/.dsh/settings.yaml`. Он один на процесс, и любое
переключение модели в композере **любой** сессии его перезаписывает: выбрать
дешёвую модель для черновой сессии значит незаметно сменить дефолт для всех
остальных. Этот плагин делает маршрут свойством **воркспейса**:

- мастер-сессии репозитория `dsh-plugins` стартуют на `zai/glm-5.3, effort=max`;
- все дочерние агенты (`subagent` / `subagent_fork` / `workflow` / `ralph`) —
  на `deepseek-official/deepseek-flash, effort=max`;
- при отказе основного маршрута по квоте/лимитам — однократная деградация на
  резервный;
- переключение модели конкретной сессии в композере работает как обычно.

## Установка

```bash
pnpm install && pnpm build && pnpm test   # в каталоге пакета
dsh plugin --profile web add ~/projects/dsh-plugins/dsh-plugin-workspace-policy
dsh --profile web --dump-config           # exit 0, строка плагина в выводе
# перезапустить профиль — хост-строки грузятся на старте
```

Конфиг строки бандла (`cordis.patch.yml`):

| Ключ             | По умолчанию          | Смысл                                    |
| ---------------- | --------------------- | ---------------------------------------- |
| `configFileName` | `.dsh/workspace.yaml` | Путь файла политики от корня воркспейса  |
| `watch`          | `true`                | Горячая перезагрузка файла               |
| `debounceMs`     | `100`                 | Дебаунс вотчера (частичная запись файла) |
| `log`            | `true`                | Информационные логи применений политики  |

## Формат `.dsh/workspace.yaml`

```yaml
model:
  default:                      # маршрут мастер-сессий этого воркспейса
    provider: zai
    model: glm-5.3
    reasoningEffort: max        # опционально
  workers:                      # все дочерние агенты
    provider: deepseek-official
    model: deepseek-flash
    reasoningEffort: max
  fallback:                     # цепочка деградации (по одной записи на отказ)
    - provider: deepseek-official
      model: deepseek-flash
budget:
  maxReasoningEffort: high      # опциональный потолок effort (только понижает)
```

- **Файл опционален.** Нет файла / пустой файл / файл без маршрутов → плагин
  полностью инертен в этом воркспейсе, ни одного сообщения в лог.
- **Сломанный файл не роняет ничего.** Невалидный YAML или форма → warning в
  host-лог с путём и причиной + инертность; при горячей правке действует
  «последний хороший» вариант до успешного репарса.
- **Секретов в файле нет и быть не должно.** Маршруты ссылаются на
  провайдеров, ключи живут в credentials-слое DSH.
- **Горячая перезагрузка.** Правка файла подхватывается (fs.watch + дебаунс).
  Сессии, уже стартовавшие до правки, маршрут не меняют; новая политика
  применяется к новым агентам.

## Семантика применения

### Мастер-сессии (`model.default`)

Замена происходит **только на первом запросе агента** (turn 1, step 1) и
только при одновременном выполнении всех условий:

1. сессия стартовала свежей (`agent/session-start` source `startup`;
   `resume` / `clear` / `compact` не трогаем — у них уже есть история);
2. в журнале сессии ещё нет `request/header` (нет записанного маршрута);
3. нет durable-записи явного выбора модели пользователем (событие
   `model/selection` с ещё не потреблённым выбором);
4. целевой провайдер зарегистрирован, модель резолвится адаптером.

После первого решения повторные запросы того же агента проходят насквозь.
**Выбор пользователя свят после первого запроса**: переключение модели в
композере немедленно действует (шов `agent/request` это решение не оспаривает),
и — благодаря пункту 3 — уважается даже выбор, сделанный в **пустой** сессии
до первого сообщения. Именно durable-событие `model/selection` закрывает
классическое ребро «предвыбор в пустой сессии неотличим от ambient-дефолта»:
композер пишет и глобальный дефолт, и сессионный `model/selection`, и плагин
слушается сессионного.

Нюанс, оставшийся на честном слове: если сессионная запись выбора по какой-то
причине не создалась (например, сессию создали API-вызовом без `select`), на
первом запросе победит политика.

### Системный промпт не врёт про модель

Сборка системного промпта (`system-prompt/assemble`) выполняется **раньше**
шва `agent/request`, поэтому без дополнительного вмешательства в промпте
первого запроса осталась бы ambient-модель (`{{model}}`), а фактический
маршрут был бы политикой — ровно то расхождение, которое видно в карточке
System prompt первой сессии. Плагин слушает и этот шов: для агента, которому
политика вот-вот применит маршрут, переменные `provider` / `model` в сборке
переставляются на маршрут политики (немодифицирующим зеркалом решения
`previewRoute`, без изменения состояния). Со второго запроса расхождение и так
невозможно: залогированный header становится источником истины для выбора
модели, и переменные сами приходят к маршруту политики. Слушатель инертен для
любого агента, которого политика не трогает, и при ошибке не меняет сборку.

### Дочерние агенты (`model.workers`) — правило абсолютности

На первом запросе **каждого** дочернего агента (честные поля
`delegationDepth > 0` / `origin: subagent'` в заголовке сессии; фолбэк-эвристика
— id без префикса `session-`) маршрут заменяется на `model.workers`.
Проверки «свежести», залогированного header и пользовательского выбора к
детям **не применяются**.

> **Важно: политика воркспейса абсолютна в своём воркспейсе.**
> `model.workers` осознанно перекрывает закрепления пресетов через
> `agentOptions` (например, `subagent_browser` в пресете `standard-browser`
> закреплён на `deepseek-v4-flash-vision-exp`). Если вам нужны точные
> закрепления детей пресетом — **не задавайте `model.workers`** в этом
> воркспейсе. Воркспейс без `workers` сохраняет до-плагиновое поведение
> дочерних агентов.

При замене ребёнка на модель без image-входа, когда исходный маршрут image
принимал, плагин пишет warning (риск `UNSUPPORTED_CONTENT` для скриншотов в
истории), но замену выполняет — конфигурируйте осознанно.

### Fallback (деградация маршрута)

Слушатель `agent/request-error`:

- реагирует только на `QUOTA` и `RATE_LIMIT`, и только когда штатная
  retry-политика отказалась ретраить (штатный обработчик `dsh-llm-retry`
  стоит выше в водопаде и сам не вызывает `next()`, когда планирует свой
  ретрай — до плагина доходят только «терминальные» отказы);
- `AUTH` / `MISSING_CREDENTIAL` / прочие коды **не** деградируют — это лечится
  ключами, не маршрутами;
- берёт следующий элемент цепочки `model.fallback` **на другом провайдере**,
  чем упавший запрос (квота аккаунт-уровневая), возвращает `{kind:'retry'}` и
  «взводит» подмену;
- повторный вход в `agent/request` видит взведённый флаг и возвращает маршрут
  из цепочки, минуя правило «только первый запрос»;
- **максимум одна подмена на шаг**: если и резервный маршрут упал в том же
  шаге — стандартная обработка ошибки; следующий элемент цепочки вооружится
  только на следующем шаге;
- индекс цепочки монотонен в течение жизни агента — циклы невозможны;
  исчерпание цепочки → стандартная обработка ошибки.

Деградация доступна любой сессии воркспейса с политикой (в том числе
возобновлённой): подменённый маршрут фиксируется как новый header сессии, и
обратно на основной маршрут сессия сама не возвращается — при необходимости
переключите модель в композере.

### Budget

`budget.maxReasoningEffort` клампит `reasoningEffort` в замещающем конфиге.
Ничего не повышает, только понижает (порядок: `off < low < medium < high < max`;
неизвестные id не упорядочиваются и проходят как есть). Если после клампа
effort не поддерживается целевой моделью — поле опускается (warning).

## Отличие от `agent-default-model`

| | `agent-default-model` | этот плагин |
| --- | --- | --- |
| Область | весь процесс, все воркспейсы | один воркспейс с файлом политики |
| Кто пишет | композер любой сессии (перетирается) | вы, в файл воркспейса (версионируется) |
| Действие | дефолт для **первых** опций агента | замена на шве `agent/request` для всех, включая детей |
| Переключения в композере | перезаписывают глобальный дефолт | уважаются после первого запроса сессии |

Плагин никогда не читает и не пишет `agent-default-model` и `saveSelection`.

## Инварианты

1. **Сквозная инертность по умолчанию**: нет конфига / конфиг невалиден /
   маршрут не зарегистрирован → `await next()` без изменений.
2. **Всегда полный конфиг**: замена — цельный `LlmCallConfig`; `temperature`,
   `maxTokens`, `stop` переносятся из базового конфига; effort — из политики.
3. **Один раз за жизнь агента** (кроме взведённого fallback).
4. **Выбор пользователя свят** после первого запроса и в пустой сессии.
5. **Сообщения не мутируются** (шов этого не позволяет).
6. **Валидация маршрута** перед заменой: провайдер в `llm.listProviders()`,
   модель резолвится `resolveModelInfo`; иначе warning + pass-through.
7. **Модальность цели**: text-only цель при image-исходнике — warning.
8. **Никаких секретов** в конфиге и логах.
9. **Обратимость**: все слушатели, вотчеры и таймеры принадлежат fiber'у
   плагина (`ctx.on` / `ctx.effect`), выгрузка не оставляет перехватов.
10. **Один host-инстанс** на процесс, без сервисов в root-realm.
11. **Живые объекты не логируются** — только листовые поля (id, маршруты).

## Верификация по журналам

Авторитетный факт о маршруте запроса — первый `request/header` журнала сессии
(`~/.dsh/sessions/<slug>/<sessionId>/session.v3.jsonl.zstd`, сжат zstd):

```bash
scripts/verify-header.sh list                 # новые сессии воркспейса
scripts/verify-header.sh first <sessionId>    # первый header сессии
scripts/verify-header.sh all <sessionId>      # все header'ы (смены маршрута)
```

Самоотчёт модели («какая ты модель?») ненадёжен — проверяйте только по
`request/header`.

## Разработка

```bash
pnpm install
pnpm typecheck   # tsc --noEmit
pnpm test        # vitest: матрица решений §7.1, парсер, стор/вотчер
pnpm build       # tsdown → lib/index.js
```

Структура: `src/decide.ts` — чистое ядро решений (без хост-объектов, полностью
покрыто юнит-тестами); `src/policy-file.ts` — парсинг/валидация YAML;
`src/policy-store.ts` — слоты per-workspace, вотчер, last-good; `src/index.ts`
— клей: слушатели `agent/session-start`, `agent/request`,
`agent/request-error`, `agent/disposed` и `system-prompt/assemble`.

## Вне scope

- per-workspace скиллы и фильтры инструментов (в реестре скиллов нет
  воркспейс-слоя; нативный путь — пресет на воркспейс);
- per-workspace инструкции (уже нативно через цепочку `AGENTS.md` и
  scope-router пользователя);
- запись в `settings.yaml` и любые `saveSelection`.
